# جدولة الشحن

[← فهرس الوثائق](../README.md)

> القواعد: BR-050–057، BR-068؛ آلة الحالة: [TRANSACTION_STATE_MACHINE.md §5](../03-architecture/TRANSACTION_STATE_MACHINE.md#5-الشحنة-shipmentsstatus).

## 1. الأدوار

| الفاعل | ما يتحكم به |
|---|---|
| المنجم | نافذة التحميل، الجاهزية، **التمديد الحصري**، توثيق المناولة |
| الناقل | موعد الاستلام المقترح داخل النافذة، حالات التنفيذ: `PICKED_UP`, `IN_TRANSIT`, `DELIVERED`، إعادة التأكيد |
| المصنع | تأكيد الاستلام النهائي |
| النظام | الجدولة بعد الدفع، المهل، `DELAYED`، الإلغاء التلقائي |

## 2. من الاتفاق إلى الجدولة

1. **عند القبول التجاري:** يحدد المنجم نافذة التحميل (`start ≥ now + 48h` افتراضيًا) وتُنشأ الشحنة `PENDING_CARRIER`.
2. **عرض النقل:** يقترح الناقل `proposed_pickup_at` داخل النافذة، ولا يسبق `now + 24h` (مهلة الدفع).
3. **التأكيد الثلاثي:** الشحنة `CARRIER_CONFIRMED`.
4. **الدفع المحاكى:** الشحنة `SCHEDULED` و`pickup_deadline_at = proposed_pickup_at`، وتُنشأ مهلة `PICKUP_DEADLINE`.
5. **التجهيز:** المنجم يعلّم `READY_FOR_PICKUP`.
6. **التنفيذ:** الناقل `PICKED_UP` (قبل الموعد + ساعتي سماح) ← `IN_TRANSIT` ← `DELIVERED`.
7. **الإغلاق:** المصنع يؤكد ← `COMPLETED`، والحجز يتحول إلى مباع.

## 3. المواعيد المحسوبة

| الحقل | الحساب |
|---|---|
| `pickup_deadline_at` | موعد العرض المختار؛ يحدثه التمديد |
| `original_pickup_deadline_at` | أول موعد مؤكد |
| موعد الإلغاء التلقائي | `pickup_deadline_at + 2h` إن لم يُستلم |
| `expected_delivery_at` | الاستلام الفعلي + المدة المتوقعة في العرض |
| حد التأخر | `expected_delivery_at + 2h` ← `DELAYED` (لا إلغاء) |
| تنبيه تأكيد الاستلام | `delivered_at + 72h` ← تنبيه الإدارة |

## 4. الشحنات في الطريق

لا إلغاء ولا تمديد بعد `PICKED_UP`. التأخر ← `DELAYED` وإشعار الأطراف والإدارة، و`DELIVERED` مسموح من `DELAYED`.

## 5. الشحنة الواحدة

الشحنة تغطي كامل كمية الصفقة ولو تطلبت عدة رحلات؛ عدد الرحلات معلومة وصفية في MVP (OD-23). `shipment_legs` تدعم النقل متعدد الأنماط مستقبلًا.

## 6. التوقيت

التخزين UTC، العرض بتوقيت الرياض (UTC+3) مع ذكر المنطقة في كل موعد.
