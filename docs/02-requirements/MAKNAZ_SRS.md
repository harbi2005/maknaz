## 1. مقدمة

### 1.1 الغرض

تحدد هذه الوثيقة متطلبات منصة **مَكْنَز** بصورة قابلة للتنفيذ والاختبار، بحيث يستطيع مهندسو الواجهات الأمامية والخلفية وقواعد البيانات وضمان الجودة والتصميم العمل باستقلالية ودون تخمين سلوك النظام.

### 1.2 تعريف المنتج

مَكْنَز **سوق رقمي B2B متخصص لمخلفات التعدين والمواد الثانوية، ومنصة لتنسيق النقل**. تربط المنصة:

- **المنجم (MINE):** بائع المادة.
- **المصنع (FACTORY):** مشتري المادة.
- **شركة النقل (CARRIER):** منفّذ النقل.
- **إدارة المنصة (ADMIN):** الإشراف والاعتماد.

تدير المنصة دورة كاملة: عرض المادة ← التفاوض ← اتفاق تجاري مبدئي ← تأكيد ناقل ← تأكيد ثلاثي ← فاتورة ودفع **محاكيان** ← شحن ← تسليم ← إغلاق، مع مهل زمنية وإلغاء تلقائي واسترجاع محاكٍ.

### 1.3 ما لا تفعله المنصة (حدود ثابتة)

- لا تحدد التركيب الكيميائي لأي مادة دون دليل مختبري مرفق، ولا تجري تحليلًا آليًا.
- لا تضمن صلاحية أي مادة للاستخدام الصناعي.
- لا تمنح ترخيصًا أو إذنًا بنقل نفايات خاضعة للتنظيم؛ بيانات التراخيص يصرّح بها أصحابها.
- لا تنفذ تحويلات مالية حقيقية ولا تصدر فواتير ضريبية معتمدة في النسخة الأولى.
- لا يتضمن النطاق الحالي ذكاءً اصطناعيًا أو تسعيرًا تنبؤيًا.

### 1.4 تصنيف المتطلبات

يحمل كل متطلب أو قرار أحد الوسوم التالية، ولا يتحول أي وسم إلى آخر دون اعتماد صريح:

| الوسم | المعنى |
|---|---|
| **APPROVED** | متطلب معتمد صراحة في وثيقة التكليف الهندسي أو وثائق المشروع المعتمدة |
| **REC** | توصية هندسية؛ تُنفّذ افتراضيًا ما لم يُعتمد بديل، ومدرجة في القرارات المفتوحة عند الحاجة |
| **ASSUMPTION** | افتراض عمل لسد فجوة في المعلومات |
| **OPEN** | قرار لم يُحسم؛ انظر [OPEN_DECISIONS.md](../08-planning/OPEN_DECISIONS.md) |
| **FUTURE** | تحسين مستقبلي خارج النسخة الأولى |

الأولوية وفق MoSCoW: **M** (Must) · **S** (Should) · **C** (Could) · **P** (Post-MVP).

| Route distance | مسافة المسار الفعلي (طريق/سكة/بحر) كما يؤكدها الناقل |
| Pickup deadline | آخر موعد مجدول لاستلام الناقل للمادة من المنجم |
| Grace period | مهلة سماح بعد الموعد قبل اتخاذ إجراء تلقائي |
| SIMULATION | وسم إلزامي لكل عملية مالية تجريبية |

## 2. الوصف العام

### 2.1 فئات المستخدمين

| النوع | المسؤولية | الوثيقة التفصيلية |
|---|---|---|
| FACTORY | البحث، عروض الشراء، اختيار الناقل، الدفع المحاكى، تأكيد الاستلام | [USE_CASES.md](USE_CASES.md) |
| MINE | إدارة المناجم والمواد، الرد على العروض، تجهيز الشحنة، **التمديد الحصري** | [USE_CASES.md](USE_CASES.md) |
| CARRIER | المواقع التشغيلية، الخدمات، قواعد التسعير، عروض النقل، تحديثات التنفيذ | [USE_CASES.md](USE_CASES.md) |
| ADMIN | اعتماد الجهات، الإشراف، الإلغاء الإداري، السجلات | [RBAC_MATRIX.md](../03-architecture/RBAC_MATRIX.md) |

داخل كل جهة توجد أدوار عضوية (`OWNER`, `MEMBER`) — **REC**؛ التفاصيل في [RBAC_MATRIX.md](../03-architecture/RBAC_MATRIX.md#2-أدوار-العضوية-داخل-الجهة).

### 2.2 بيئة التشغيل

- تطبيق ويب متجاوب يعمل على متصفحات سطح المكتب والجوال (انظر NFR-040 إلى NFR-043).
- اللغة الافتراضية العربية (RTL)، مع مصطلحات تقنية إنجليزية عند الحاجة.
- المنطقة الزمنية للعرض: `Asia/Riyadh`، والتخزين بتوقيت UTC.
- العملة: الريال السعودي `SAR` في النسخة الأولى.

### 2.3 القيود

| القيد | التصنيف |
|---|---|
| مدة بناء النسخة الأولى 8 أيام بفريق صغير | APPROVED |
| لا بوابة دفع ولا تحويلات حقيقية ولا ضمان مالي (escrow) | APPROVED |
| لا واجهة إدارية لتعديل السياسات الزمنية في النسخة الأولى | APPROVED |
| لا تكامل مع خدمات توجيه مسارات مدفوعة دون اعتماد | REC |
| لا بيانات لشركات أو أسعار حقيقية؛ بيانات العرض موسومة «تجريبية» | APPROVED |
