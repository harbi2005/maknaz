# قواعد العمل — مَكْنَز | MAKNAZ

[← فهرس الوثائق](../README.md) · [SRS](MAKNAZ_SRS.md)

تحدد هذه الوثيقة القواعد التي يجب أن تفرضها **طبقة الخدمة على الخادم** بغض النظر عن الواجهة. كل قاعدة موسومة بتصنيفها (APPROVED / REC / OPEN) وفق [SRS §1.4](MAKNAZ_SRS.md#14-تصنيف-المتطلبات).

---

## 1. الجهات والوصول

| ID | القاعدة | تصنيف |
|---|---|---|
| BR-001 | لكل جهة نوع واحد ثابت: `FACTORY` أو `MINE` أو `CARRIER`؛ لا يتغير النوع بعد الإنشاء | ASSUMPTION (OD-14) |
| BR-002 | الجهة بحالة `PENDING_REVIEW` أو `REJECTED` أو `SUSPENDED` لا تنشر عروضًا ولا تقدم عروض شراء أو نقل ولا تدفع؛ تستطيع تعديل ملفها فقط | REC (OD-24) |
| BR-003 | كل إجراء على مورد جهة يتطلب أن يكون المستخدم عضوًا نشطًا فيها؛ الدور وحده لا يكفي | APPROVED |
| BR-004 | لا يطّلع أي طرف على بيانات جهة أخرى إلا ما تحدده [RBAC_MATRIX.md](../03-architecture/RBAC_MATRIX.md) | APPROVED |
| BR-005 | تعليق جهة لا يلغي صفقاتها القائمة تلقائيًا؛ تُعرض للإدارة للمعالجة اليدوية | REC |

## 2. المواد والمخزون

| ID | القاعدة | تصنيف |
|---|---|---|
| BR-010 | الكمية المتاحة = `total_quantity − reserved_quantity − sold_quantity`، ويجب أن تكون ≥ 0 دائمًا | APPROVED |
| BR-011 | لكل مواصفة حالة تحقق: `LAB_REPORTED` (مدعومة بتقرير مرفق)، `DECLARED` (مصرّح بها دون مستند)، `ESTIMATED` (تقدير)، `UNKNOWN` (غير معروفة) | APPROVED |
| BR-012 | `LAB_REPORTED` تتطلب `document_id` لوثيقة مختبرية مرفوعة لنفس العرض؛ النظام لا يتحقق من صحة محتوى التقرير ويعرض «مدعوم بتقرير مرفق من المنجم» لا «موثّق من المنصة» | APPROVED |
| BR-013 | لا تعرض المنصة أي حكم بصلاحية المادة أو تركيبها | APPROVED |
| BR-014 | نشر العرض يتطلب: فئة، وحدة، كمية كلية > 0، سعر طلب > 0، منجم نشط، شروط تحميل، جهة `ACTIVE` | REC |
| BR-015 | لا يجوز خفض الكمية الكلية تحت `reserved + sold` | APPROVED |
| BR-016 | إيقاف العرض أو أرشفته يحول عروض الشراء المفتوحة عليه إلى `EXPIRED` بسبب `LISTING_INACTIVE`، ولا يمس الصفقات القائمة | REC |
| BR-017 | إتاحة الوثائق: `PUBLIC` لكل جهة نشطة؛ `ON_REQUEST` للمصنع الذي لديه عرض شراء مفتوح أو صفقة على العرض؛ `PRIVATE` للمنجم المالك والإدارة فقط. الافتراضي `ON_REQUEST` | REC (OD-17) |
| BR-018 | تعديل سعر الطلب أو الوصف لا يغير أي عرض شراء قائم أو صفقة | APPROVED |
| BR-019 | الوحدة الأساسية الطن المتري بدقة 3 خانات عشرية | ASSUMPTION (OD-21) |

## 3. عروض الشراء والتفاوض

| ID | القاعدة | تصنيف |
|---|---|---|
| BR-020 | عرض الشراء يتطلب: عرض مادة `ACTIVE`، جهة مصنع `ACTIVE`، موقع تسليم للجهة نفسها، كمية > 0 و≤ المتاح وقت التقديم، سعر وحدة > 0 | APPROVED + REC |
| BR-021 | عرض شراء مفتوح واحد (`SUBMITTED` أو `COUNTERED`) لكل مصنع على كل عرض مادة | REC (OD-03) |
| BR-022 | يرد المنجم على جولة المصنع بأحد: قبول، رفض، عرض مقابل. العرض المقابل مرة واحدة لكل عرض شراء، بسعر مختلف، ويجوز أن يخفض الكمية ولا يزيدها | APPROVED + REC (OD-04) |
| BR-023 | يرد المصنع على العرض المقابل بالقبول أو الرفض فقط؛ بعد الرفض يجوز تقديم عرض شراء جديد | APPROVED |
| BR-024 | لكل جولة `expires_at` = وقت الإنشاء + `offer_round_validity` (48 ساعة)؛ الجولة المنتهية لا تُقبل، وتتحول الحالة إلى `EXPIRED` بمهمة خلفية أو عند أول محاولة قبول | APPROVED + REC |
| BR-025 | الجولات غير قابلة للتعديل بعد الإنشاء؛ آخر جولة هي «السعر الحالي» | APPROVED |
| BR-026 | السعر المتفق عليه = سعر وكمية الجولة المقبولة، ويُنسخ إلى لقطة الصفقة | APPROVED |
| BR-027 | تُحجز الكمية لحظة الاتفاق: قبول المنجم لجولة المصنع، أو قبول المصنع للعرض المقابل. لا حجز عند مجرد التقديم | REC (OD-02) |
| BR-028 | الحجز تحديث ذري مشروط: `UPDATE material_listings SET reserved_quantity = reserved_quantity + :q WHERE id = :id AND total_quantity - reserved_quantity - sold_quantity >= :q`. إن لم يتأثر صف يُرفض القبول بـ `INSUFFICIENT_QUANTITY` ولا تُنشأ صفقة | APPROVED |
| BR-029 | قبول متزامن لعرضين لا يتجاوز مجموعهما المتاح ينجحان؛ إن تجاوز ينجح أحدهما فقط | APPROVED |

## 4. الصفقات والناقلون

| ID | القاعدة | تصنيف |
|---|---|---|
| BR-030 | الصفقة تُنشأ عند الاتفاق بحالة `PENDING_CARRIER`، و`carrier_deadline_at` = `agreed_at + 24h` | APPROVED |
| BR-031 | الأهلية (كلها إلزامية): الجهة `ACTIVE`؛ خدمة تدعم `cargo_class` لفئة المادة؛ النمط مفعّل (`ROAD` في النسخة الأولى)؛ `min_shipment_tons ≤ كمية الصفقة ≤ max_shipment_tons`؛ منطقة خدمة تشمل منطقة المنجم ومنطقة المصنع؛ إصدار تسعير `ACTIVE` ساري في وقت الطلب | APPROVED |
| BR-032 | ترتيب المؤهلين بنطاق المسافة المباشرة من أقرب موقع تشغيلي نشط إلى المنجم: `B1` 0–50، `B2` 51–150، `B3` 151–300، `B4` > 300 كم، ثم بالمسافة داخل النطاق. النطاقات قيم هندسية قابلة للضبط وليست أنظمة نقل | APPROVED |
| BR-033 | المسافة المباشرة (Haversine) تُعرض دائمًا بوسم «مسافة مباشرة تقريبية»؛ مسافة المسار يؤكدها الناقل في عرضه | APPROVED |
| BR-034 | تقديم عرض النقل يعني قبول الناقل للشحنة والتزامه بالسعر وموعد الاستلام المقترح حتى `expires_at` | REC (OD-01) |
| BR-035 | `quote.expires_at` = موعد انتهاء المهلة الحالية للصفقة (`carrier_deadline_at` أو `retry_deadline_at`) | REC |
| BR-036 | يختار المصنع عرضًا صالحًا واحدًا، وليس بالضرورة الأول أو الأرخص؛ يكتمل بذلك التأكيد الثلاثي | REC (OD-01) |
| BR-037 | إذا انقضت `carrier_deadline_at` دون تأكيد ثلاثي تنتقل الصفقة إلى `PENDING_CARRIER_RETRY` مرة واحدة بمهلة 24 ساعة؛ إذا انقضت دون تأكيد تُلغى تلقائيًا بسبب `NO_CARRIER_CONFIRMED` ويُحرر الحجز | APPROVED |
| BR-038 | في فترة إعادة المحاولة تتسع المطابقة إلى النطاق التالي، ويُعاد إشعار الناقلين المؤهلين، وتبقى العروض الصالحة السابقة قابلة للاختيار مع تمديد صلاحيتها إلى `retry_deadline_at` | REC (OD-05) |
| BR-039 | شروط التأكيد الثلاثي: الصفقة `PENDING_CARRIER` أو `PENDING_CARRIER_RETRY`؛ الحجز `ACTIVE`؛ العرض `SUBMITTED` وغير منتهٍ؛ جهة الناقل `ACTIVE`؛ موعد الاستلام داخل نافذة التحميل ولا يسبق `now + payment_window` | APPROVED + REC |
| BR-040 | التأكيد الثلاثي معاملة واحدة: العرض المختار `SELECTED` وباقي العروض `NOT_SELECTED`؛ الشحنة `CARRIER_CONFIRMED`؛ الفاتورة تُنشأ؛ الصفقة `AWAITING_PAYMENT` و`payment_deadline_at = now + 24h` | APPROVED |

## 5. الفواتير والمدفوعات المحاكاة

| ID | القاعدة | تصنيف |
|---|---|---|
| BR-041 | لا دفع ولا فاتورة قبل التأكيد الثلاثي | APPROVED |
| BR-042 | الدفع المحاكى: عضو جهة المصنع صاحبة الصفقة فقط، والصفقة `AWAITING_PAYMENT`، و`now < payment_deadline_at` | APPROVED |
| BR-043 | `Idempotency-Key` إلزامي؛ نفس المفتاح ونفس الجسم يعيد النتيجة المحفوظة؛ نفس المفتاح بجسم مختلف يعيد `409 IDEMPOTENCY_KEY_REUSED`؛ ودفعة `COMPLETED` واحدة لكل فاتورة بفهرس فريد جزئي | APPROVED |
| BR-044 | انقضاء `payment_deadline_at` دون دفع: الفاتورة `PAYMENT_EXPIRED`، الصفقة `CANCELLED` بسبب `PAYMENT_EXPIRED`، الحجز يُحرر، العرض المختار `RELEASED`، الشحنة `CANCELLED` | APPROVED |
| BR-045 | كل سجل مالي يحمل `is_simulated = true` ووسم `DEMO / SIMULATION`؛ لا يوصف بأنه فاتورة ضريبية، ولا تُحتسب ضريبة | APPROVED (OD-12) |
| BR-046 | أهلية الاسترجاع: إلغاء بعد دفعة `COMPLETED` وقبل `PICKED_UP` ← استرجاع كامل؛ إعادة إسناد بسعر نقل أقل ← استرجاع جزئي للفرق (OD-07)؛ لا استرجاع عبر النظام بعد `PICKED_UP` (معالجة نزاعات Post-MVP) | APPROVED + REC |
| BR-047 | مجموع الاستردادات لكل فاتورة ≤ المبلغ المدفوع؛ مفروض بقفل صف الفاتورة والتحقق قبل الإنشاء | APPROVED |
| BR-048 | الاسترجاع المحاكى ينتقل `INITIATED` ← `COMPLETED` فورًا في المهمة نفسها؛ الحالة الوسيطة محفوظة للتدقيق | REC |

## 6. الشحنات والتمديد

| ID | القاعدة | تصنيف |
|---|---|---|
| BR-050 | تُنشأ الشحنة مع الصفقة بحالة `PENDING_CARRIER`، وتحمل `pickup_window_start/end` من نافذة التحميل التي حددها المنجم | REC |
| BR-051 | يحدد المنجم نافذة التحميل عند القبول (أو عند إنشاء العرض المقابل)، ويقترح الناقل `proposed_pickup_at` داخلها | APPROVED + REC |
| BR-052 | بعد الدفع: `pickup_deadline_at` = `proposed_pickup_at` للعرض المختار، والحالة `SCHEDULED` | REC |
| BR-053 | الناقل المسند وحده يغير `PICKED_UP`, `IN_TRANSIT`, `DELIVERED` | APPROVED |
| BR-054 | المنجم يغير `READY_FOR_PICKUP` ويوثق المناولة | APPROVED |
| BR-055 | المصنع وحده يؤكد الاستلام ← `COMPLETED`، وينقل الحجز إلى «مباع» | APPROVED |
| BR-056 | لا تأكيد استلام تلقائي في النسخة الأولى؛ بعد 72 ساعة من `DELIVERED` دون تأكيد تُنبَّه الإدارة | REC (OD-09) |
| BR-057 | `expected_delivery_at` = `pickup` الفعلي + المدة المتوقعة في العرض المختار | REC |
| BR-060 | المنجم المالك للصفقة وحده يملك تمديد موعد الاستلام | APPROVED |
| BR-061 | حد أقصى تمديدان لكل شحنة؛ `new_deadline − current_deadline ≤ 72h` و> 0؛ السبب نص إلزامي (10–500 حرف) ورمز سبب؛ الإشعار والتدقيق إلزاميان | APPROVED |
| BR-062 | التمديد مسموح في `SCHEDULED`, `READY_FOR_PICKUP`, `RECONFIRM_REQUIRED`, `PENDING_CARRIER` (أثناء إعادة الإسناد)، وفقط قبل `pickup_deadline_at + pickup_grace_period`؛ ممنوع من `PICKED_UP` فما بعد | REC |
| BR-063 | لا موافقة للمصنع على التمديد، ولا يملك الناقل منعه أو إلغاءه | APPROVED |
| BR-064 | بعد التمديد (إذا كان هناك ناقل مسند) تصبح الشحنة `RECONFIRM_REQUIRED` و`reconfirm_deadline_at` = الأقرب بين `now + 12h` و`new_pickup_deadline − 2h`؛ وإذا كان الأقرب في الماضي يُستخدم `now + 1h` | REC (OD-06) |
| BR-065 | اعتذار الناقل أو انقضاء مهلة إعادة التأكيد: يبقى الموعد الجديد ساريًا (سلطة المنجم)؛ العرض المسند `RELEASED`؛ الشحنة `PENDING_CARRIER` بمهلة `reassignment_window` 24 ساعة؛ تبقى الصفقة `PAID` | REC (OD-07) |
| BR-066 | إعادة الإسناد بعد الدفع: عرض بسعر ≤ النقل المفوتر يُقبل مباشرة عند اختيار المصنع ويُنشأ استرجاع جزئي للفرق؛ عرض بسعر أعلى يتطلب موافقة صريحة من المصنع على فرق السعر (لا على التمديد) ويُصدر بند تسوية بدفعة محاكاة إضافية؛ انقضاء `reassignment_window` دون إسناد ← إلغاء تلقائي واسترجاع كامل | REC (OD-07) |
| BR-067 | التمديد لا يغير مهلة الدفع؛ الدفع يسبق الشحن دائمًا | REC |
| BR-068 | في نسخة MVP لا تُعاد جدولة الشحنة التي بلغت `PICKED_UP`؛ تأخر النقل يُعالج بحالة `DELAYED` | APPROVED |

## 7. المهل والإلغاء التلقائي

### 7.1 قيم السياسة

| المفتاح | القيمة | البداية | الإجراء عند الانقضاء | تصنيف |
|---|---|---|---|---|
| `carrier_confirmation_window` | 24h | `deal.agreed_at` | ← `PENDING_CARRIER_RETRY` | APPROVED |
| `carrier_retry_window` | 24h (مرة واحدة) | `carrier_deadline_at` | ← `CANCELLED (NO_CARRIER_CONFIRMED)` | APPROVED |
| `payment_window` | 24h | `invoice.issued_at` | ← `CANCELLED (PAYMENT_EXPIRED)` | APPROVED |
| `pickup_grace_period` | 2h | `pickup_deadline_at` | إن لم تُستلم ← `CANCELLED (PICKUP_MISSED)` + استرجاع كامل | APPROVED + REC |
| `max_shipment_extensions` | 2 | — | رفض التمديد الثالث | APPROVED |
| `max_extension_hours` | 72h | `current pickup_deadline_at` | رفض ما يتجاوزها | APPROVED |
| `auto_cancellation_enabled` | true | — | — | APPROVED |
| `offer_round_validity` | 48h | إنشاء الجولة | ← `EXPIRED` | REC (OD-03) |
| `carrier_reconfirm_window` | min(12h, حتى `deadline − 2h`) | التمديد | ← إعادة إسناد | REC (OD-06) |
| `reassignment_window` | 24h | تحرير الناقل | ← `CANCELLED (NO_CARRIER_REASSIGNED)` + استرجاع كامل | REC (OD-07) |
| `delivery_grace_period` | 2h | `expected_delivery_at` | ← `DELAYED` + تنبيه الإدارة (لا إلغاء) | REC |
| `delivered_unconfirmed_alert` | 72h | `delivered_at` | تنبيه الإدارة | REC (OD-09) |
