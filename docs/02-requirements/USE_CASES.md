## UC-001 — تسجيل الجهة والحساب

| | |
|---|---|
| الفاعل الرئيسي | مستخدم جديد |
| المساندون | ADMIN (لاحقًا في UC-021)، خدمة البريد |
| الوصف | إنشاء حساب مستخدم وجهة بنوع محدد وإكمال ملفها |
| المحفز | زيارة صفحة التسجيل |
| الشروط المسبقة | البريد غير مسجل |

**السيناريو الرئيسي**
1. يدخل المستخدم الاسم والبريد وكلمة المرور ويقبل الشروط.
2. يرسل النظام رابط تحقق ويُنشئ المستخدم بحالة `UNVERIFIED`.
3. يتحقق المستخدم من البريد.
4. يختار نوع الجهة (مصنع/منجم/ناقل) ويدخل: الاسم العربي والإنجليزي، رقم السجل التجاري، المدينة، بيانات التواصل.
5. يُنشئ النظام الجهة بحالة `PENDING_REVIEW` والمستخدم `OWNER`.
6. المصنع يضيف موقع مصنع واحدًا على الأقل؛ الناقل يضيف موقعًا تشغيليًا واحدًا على الأقل؛ المنجم يضيف منجمًا (UC-002).
7. يرسل النظام طلب الاعتماد للإدارة ويعرض للمستخدم حالة «قيد المراجعة».

**البديلة:** 4أ. الناقل والمنجم يضيفان تراخيص مصرّحًا بها (اختياري). 5أ. مستخدم مدعو ينضم لجهة قائمة بدور `MEMBER` دون إنشاء جهة.
**الاستثناءات:** E1 البريد مسجل ← رسالة عامة دون كشف الوجود. E2 رقم سجل مكرر لنفس النوع ← `409 DUPLICATE_REGISTRATION`. E3 رابط تحقق منتهٍ ← إعادة الإرسال.
**الشروط اللاحقة:** مستخدم مُتحقق، جهة `PENDING_REVIEW`، سجل تدقيق.
**القواعد:** BR-001، BR-002، BR-090. **الصلاحيات:** P-01، P-02، P-04.
**البيانات:** users، organizations، organization_members، organization_licenses، factory_sites، carrier_operating_locations.
**معايير القبول:**
- AC1: لا يستطيع مستخدم غير متحقق إنشاء جهة.
- AC2: الجهة الجديدة لا تظهر في البحث ولا تنفذ أي إجراء تجاري قبل الاعتماد.
- AC3: كلمة المرور ≥ 10 أحرف وتُخزن مجزأة.

## UC-002 — تسجيل منجم

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة MINE |
| الوصف | إضافة موقع تعديني بإحداثياته ونشاطه |
| المحفز | «إضافة منجم» |
| الشروط المسبقة | جهة MINE (أي حالة للإنشاء، `ACTIVE` للظهور) |

**السيناريو الرئيسي**
1. يدخل الاسم، النشاط التعديني الرئيسي، المنطقة الإدارية، العنوان الوصفي.
2. يختار الموقع على الخريطة أو يدخل lat/lng.
3. يتحقق النظام من الإحداثيات (−90..90، −180..180، وداخل المملكة في MVP).
4. يُنشئ المنجم بحالة `ACTIVE` ويظهر للجهات النشطة إذا كانت الجهة `ACTIVE`.

**البديلة:** 2أ. تعديل لاحق للإحداثيات مسموح إن لم توجد صفقات قائمة على مواده؛ وإلا يُرفض لحماية لقطات المسافة.
**الاستثناءات:** E1 إحداثيات خارج النطاق ← `422 INVALID_COORDINATES`.
**الشروط اللاحقة:** منجم مرتبط بالجهة. **القواعد:** BR-003. **الصلاحيات:** P-10.
**البيانات:** mines.
**معايير القبول:** AC1 لا يرى منجمٌ آخر زر تعديل هذا المنجم، وطلب PATCH مباشر يعيد `404`. AC2 الإيقاف لا يغير الصفقات القائمة.

## UC-003 — إنشاء عرض مادة ونشره

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة MINE |
| المساندون | ADMIN (فئات المواد) |
| الوصف | تسجيل مادة ثانوية متاحة بمواصفاتها ووثائقها وسعرها |
| المحفز | «إضافة مادة» |
| الشروط المسبقة | جهة `ACTIVE`، منجم `ACTIVE` |

**السيناريو الرئيسي**
1. يختار المنجم المصدر والفئة.
2. يدخل الاسم، الوصف، الحالة الفيزيائية، الكمية الكلية (طن)، سعر الطلب (ر.س/طن)، قابلية التفاوض، شروط التحميل، نافذة الجاهزية.
3. يضيف المواصفات: الخاصية، القيمة، الوحدة، حالة التحقق.
4. يرفع وثائق المختبر ويحدد إتاحتها، ويربط المواصفات `LAB_REPORTED` بها.
5. يحفظ العرض `DRAFT`، ثم يضغط «نشر».
6. يتحقق النظام من الحقول الإلزامية ويحول الحالة إلى `ACTIVE`.

**البديلة:** 3أ. خاصية مجهولة ← حالة `UNKNOWN` دون قيمة. 6أ. إيقاف لاحق ← `INACTIVE` وتنتهي العروض المفتوحة.
**الاستثناءات:** E1 `LAB_REPORTED` دون وثيقة ← `422 LAB_DOCUMENT_REQUIRED`. E2 ملف غير مسموح ← `415`. E3 حقل إلزامي ناقص عند النشر ← `422` بقائمة الحقول.
**الشروط اللاحقة:** عرض `ACTIVE` قابل للبحث. **القواعد:** BR-010–018. **الصلاحيات:** P-20–P-25.
**البيانات:** material_listings، material_specifications، material_documents، material_categories.
**معايير القبول:**
- AC1: كل مواصفة تظهر للمشتري بوسم حالتها.
- AC2: لا تظهر عبارة «موثّق من المنصة» في أي مكان.
- AC3: تعديل السعر لا يغير أسعار عروض الشراء القائمة.

## UC-004 — البحث عن المواد واستعراضها

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة FACTORY |
| الوصف | اكتشاف المواد ومقارنتها وفتح تفاصيلها |
| الشروط المسبقة | جهة `ACTIVE` |

**السيناريو الرئيسي**
1. يفتح صفحة البحث ويختار موقع المصنع المرجعي للمسافة.
2. يبحث بالنص ويصفّي بالفئة والمنطقة والكمية والسعر.
3. يعرض النظام النتائج قائمة وخريطة مع المسافة المباشرة الموسومة.
4. يفتح تفاصيل مادة: البيانات، المواصفات، الوثائق المتاحة، المنجم.
5. ينزّل وثيقة `PUBLIC`.

**البديلة:** 5أ. وثيقة `ON_REQUEST` ← تُتاح بعد تقديم عرض شراء (UC-005). 3أ. لا نتائج ← حالة فارغة مع اقتراح توسيع المرشحات.
**الاستثناءات:** E1 عرض أُوقف أثناء التصفح ← `404` مع رسالة «لم يعد متاحًا».
**القواعد:** BR-017، BR-033. **الصلاحيات:** P-11، P-24، P-26، P-27.
**البيانات:** material_listings، mines، material_specifications، material_documents، factory_sites.
**معايير القبول:** AC1 المسافة موسومة «مباشرة تقريبية». AC2 الكمية المعروضة هي المتاحة لا الكلية. AC3 p95 ≤ 1s على 10,000 عرض.

## UC-005 — تقديم عرض شراء

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة FACTORY |
| المساندون | MINE (يستقبل) |
| الوصف | عرض كمية وسعر وحدة على مادة |
| الشروط المسبقة | جهة `ACTIVE`، عرض مادة `ACTIVE`، لا عرض مفتوح للمصنع على المادة نفسها |

**السيناريو الرئيسي**
1. من صفحة المادة يختار «تقديم عرض».
2. يدخل الكمية، سعر الوحدة المقترح (افتراضيًا سعر الطلب)، موقع التسليم، ملاحظات.
3. يعرض النظام ملخص قيمة المادة (الكمية × السعر) وتنبيهًا بأن النقل يُحسب لاحقًا.
4. يرسل؛ يُنشئ النظام `purchase_offer` بحالة `SUBMITTED` والجولة 1 (`proposed_by = FACTORY`) بمهلة 48 ساعة.
5. يُشعر المنجم.

**البديلة:** 6أ. يسحب المصنع العرض قبل الرد ← `WITHDRAWN`.
**الاستثناءات:** E1 كمية > المتاح ← `422 QUANTITY_EXCEEDS_AVAILABLE`. E2 عرض مفتوح قائم ← `409 OPEN_OFFER_EXISTS`. E3 موقع تسليم لجهة أخرى ← `404`.
**الشروط اللاحقة:** عرض وجولة محفوظان؛ لا حجز. **القواعد:** BR-020، BR-021، BR-024. **الصلاحيات:** P-30، P-32.
**البيانات:** purchase_offers، offer_negotiation_rounds.
**معايير القبول:** AC1 لا تتغير الكمية المحجوزة عند التقديم. AC2 الجولة غير قابلة للتعديل.

## UC-006 — عرض مقابل من المنجم

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة MINE |
| المساندون | FACTORY |
| الشروط المسبقة | العرض `SUBMITTED`، الجولة 1 غير منتهية، لا عرض مقابل سابق |

**السيناريو الرئيسي**
1. يفتح المنجم العرض ويختار «عرض مقابل».
2. يدخل سعر الوحدة الجديد، والكمية (≤ الأصلية)، ونافذة التحميل، ورسالة.
3. يُنشئ النظام الجولة 2 (`proposed_by = MINE`) بمهلة 48 ساعة، ويغلق الجولة 1 بنتيجة `COUNTERED`، والعرض ← `COUNTERED`.
4. يُشعر المصنع، الذي يقبل (UC-008) أو يرفض (UC-007).

**الاستثناءات:** E1 سعر مطابق للحالي ← `422 COUNTER_PRICE_UNCHANGED`. E2 كمية أكبر ← `422`. E3 الجولة منتهية ← `409 ROUND_EXPIRED`.
**القواعد:** BR-022، BR-025. **الصلاحيات:** P-35.
**البيانات:** offer_negotiation_rounds، purchase_offers.
**معايير القبول:** AC1 لا يمكن إنشاء عرض مقابل ثانٍ. AC2 المصنع لا يملك زر «عرض مقابل».

## UC-007 — رفض العرض

| | |
|---|---|
| الفاعل الرئيسي | MINE (يرفض جولة المصنع) أو FACTORY (يرفض العرض المقابل) |
| الشروط المسبقة | العرض `SUBMITTED` (للمنجم) أو `COUNTERED` (للمصنع) |

**السيناريو الرئيسي:** 1. يختار «رفض» مع سبب اختياري. 2. الجولة ← `REJECTED`، والعرض ← `REJECTED`. 3. يُشعر الطرف الآخر.
**البديلة:** 3أ. بعد الرفض يقدم المصنع عرضًا جديدًا (UC-005).
**الاستثناءات:** E1 حالة لا تسمح ← `409 INVALID_STATE`.
**القواعد:** BR-022، BR-023. **الصلاحيات:** P-34، P-36. **البيانات:** purchase_offers، offer_negotiation_rounds.
**معايير القبول:** AC1 لا حجز ولا صفقة. AC2 السجل الكامل للجولات يبقى مقروءًا للطرفين.

## UC-008 — القبول التجاري وإنشاء الصفقة

| | |
|---|---|
| الفاعل الرئيسي | MINE (يقبل جولة المصنع) أو FACTORY (يقبل العرض المقابل) |
| المساندون | SYSTEM، الناقلون المؤهلون |
| الوصف | الاتفاق على السعر والكمية، حجز المخزون، إنشاء الصفقة والشحنة، فتح فرصة النقل |
| الشروط المسبقة | جولة سارية غير منتهية؛ جهة الطرفين `ACTIVE`؛ نافذة تحميل محددة |

**السيناريو الرئيسي**
1. يضغط القابل «قبول» (المنجم يحدد نافذة التحميل إن لم تحدد في العرض المقابل) مع `Idempotency-Key`.
2. يبدأ النظام معاملة قاعدة بيانات:
   1. تحديث مشروط للجولة: `status = PENDING AND expires_at > now` ← `ACCEPTED`.
   2. حجز ذري للكمية (BR-028).
   3. إنشاء `inventory_reservation` بحالة `ACTIVE`.
   4. إنشاء `deal` بحالة `PENDING_CARRIER` بلقطة تجارية و`carrier_deadline_at = now + 24h` و`policy_version_id`.
   5. إنشاء `shipment` بحالة `PENDING_CARRIER`.
   6. إنشاء `scheduled_deadline` من نوع `CARRIER_CONFIRMATION`.
   7. العرض ← `ACCEPTED`.
3. بعد الالتزام: حساب الناقلين المؤهلين (UC-009) وإشعارهم وإشعار الطرفين.

**البديلة:** 1أ. قبول المصنع للعرض المقابل يتبع الخطوات نفسها.
**الاستثناءات:** E1 الكمية غير كافية ← تراجع كامل، `409 INSUFFICIENT_QUANTITY`، الجولة تبقى `PENDING`. E2 الجولة منتهية ← `409 ROUND_EXPIRED` والجولة ← `EXPIRED`. E3 طلب مكرر بنفس المفتاح ← النتيجة نفسها.
**الشروط اللاحقة:** صفقة وشحنة ومهلة؛ المتاح انخفض بمقدار الكمية.
**القواعد:** BR-026–030، BR-050–051. **الصلاحيات:** P-33، P-36.
**البيانات:** deals، inventory_reservations، material_listings، shipments، scheduled_deadlines.
**معايير القبول:**
- AC1: 50 قبولًا متزامنًا على مادة متاحها 100 طن بعروض 10 أطنان ← 10 صفقات بالضبط.
- AC2: سعر الصفقة = سعر الجولة المقبولة ولا يتغير لاحقًا.
- AC3: لا صفقة دون حجز `ACTIVE`.

## UC-009 — اكتشاف الناقلين جغرافيًا

| | |
|---|---|
| الفاعل الرئيسي | SYSTEM (حساب)، CARRIER (استعراض الفرص)، FACTORY (استعراض المؤهلين) |
| الشروط المسبقة | صفقة `PENDING_CARRIER*` |

**السيناريو الرئيسي**
1. يحدد النظام `cargo_class` من فئة المادة، والكمية، ومنطقتي المنجم والمصنع.
2. يطبق مرشحات الأهلية (BR-031) على `carrier_services` و`carrier_service_areas` وإصدارات التسعير السارية.
3. لكل ناقل مؤهل يحسب المسافة المباشرة من أقرب موقع تشغيلي نشط إلى المنجم، ويصنفها في نطاق.
4. يرتب حسب النطاق ثم المسافة، ويعرض للمصنع مع تقدير أولي للسعر من القاعدة (موسوم «تقدير»).
5. يرى الناقل الفرصة في «فرص الشحن» مع تصفية بالمنطقة والنطاق.

**البديلة:** 2أ. لا مؤهلين ← تُعرض حالة فارغة ويُنتظر حتى فترة إعادة المحاولة التي تُعيد الحساب.
**الاستثناءات:** E1 موقع تشغيلي بلا إحداثيات ← يُستبعد ويُسجل تحذير.
**القواعد:** BR-031–033، BR-038. **الصلاحيات:** P-44، P-48.
**البيانات:** carrier_operating_locations، carrier_services، carrier_service_areas، carrier_pricing_rule_versions، mines، factory_sites.
**معايير القبول:** AC1 ناقل قريب لا يدعم صنف الحمولة لا يظهر. AC2 ناقل خدمته الدنيا 1,000 طن لا يظهر لصفقة 600 طن. AC3 المسافة موسومة «مباشرة».

## UC-010 — حساب عرض النقل وتقديمه

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة CARRIER |
| الشروط المسبقة | ناقل مؤهل، صفقة `PENDING_CARRIER*`، لا عرض `SUBMITTED` آخر له على الصفقة |

**السيناريو الرئيسي**
1. يفتح الناقل الفرصة ويرى: المادة وصنف الحمولة، الكمية، المنجم والمصنع، نافذة التحميل، المسافة المباشرة وتقدير مسافة الطريق الموسوم.
2. يختار الخدمة (المركبة)، ويؤكد `route_distance_km`، ويقترح `proposed_pickup_at` داخل النافذة، والمدة المتوقعة.

5. يُنشئ النظام `transport_quote` بحالة `SUBMITTED` و`expires_at` = مهلة الصفقة، مع `pricing_snapshot` و`pricing_rule_version_id`.
6. يُشعر المصنع والمنجم.

**البديلة:** 4أ. يسحب الناقل العرض ← `WITHDRAWN`.
**الاستثناءات:** E1 الكمية خارج حدود الخدمة ← `422 CAPACITY_MISMATCH`. E2 موعد خارج النافذة أو قبل `now + payment_window` ← `422 PICKUP_OUTSIDE_WINDOW`. E3 لا إصدار ساري ← `409 NO_ACTIVE_PRICING`. E4 مسافة طريق < المسافة المباشرة ← `422 ROUTE_DISTANCE_TOO_SHORT`.

**البيانات:** transport_quotes، carrier_pricing_rule_versions، carrier_services.
**معايير القبول:** AC1 حقل السعر المرسل من العميل يُرفض. AC2 لقطة التسعير تكفي لإعادة حساب الرقم نفسه. AC3 تعديل الناقل لقاعدته لاحقًا لا يغير العرض.

| `PAYMENT` | الصفقة `AWAITING_PAYMENT` | ← `CANCELLED (PAYMENT_EXPIRED)`، الفاتورة `PAYMENT_EXPIRED`، تحرير الحجز والناقل |
| `PICKUP_DEADLINE` | الشحنة `SCHEDULED`/`READY_FOR_PICKUP`/`RECONFIRM_REQUIRED` عند `deadline + 2h` | ← `CANCELLED (PICKUP_MISSED)` + UC-020 |
| `CARRIER_RECONFIRM` | الشحنة `RECONFIRM_REQUIRED` | ← إعادة الإسناد (UC-016) |
| `REASSIGNMENT` | الشحنة `PENDING_CARRIER` بعد الدفع | ← `CANCELLED (NO_CARRIER_REASSIGNED)` + UC-020 |
| `DELIVERY_ETA` | الشحنة `IN_TRANSIT` عند `expected + 2h` | ← `DELAYED` + تنبيه الإدارة (لا إلغاء) |
| `OFFER_ROUND` | الجولة `PENDING` | ← `EXPIRED` |

إذا لم تطابق الحالة الشرط ← المهلة `SKIPPED`. بعد النجاح ← `DONE`.

**الاستثناءات:** E1 فشل التنفيذ ← `attempts + 1` وإعادة بتراجع أسي حتى 5 مرات، ثم `FAILED` وتنبيه. E2 تشغيل متوازٍ لمثيلين ← `SKIP LOCKED` يمنع التنفيذ المزدوج.
**القواعد:** BR-037، BR-044، BR-071–077. **البيانات:** scheduled_deadlines وكل الكيانات المتأثرة.
**معايير القبول:** AC1 تشغيل المهمة مرتين على المهلة نفسها لا يكرر الإلغاء أو الاسترجاع. AC2 شحنة `PICKED_UP` لا تُلغى أبدًا تلقائيًا. AC3 أقصى تأخر للتنفيذ دقيقتان.

## UC-024 — تحديث حالة النقل والتأخر

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة CARRIER المسند |

**السيناريو الرئيسي:** 1. بعد `PICKED_UP` يعلّم «في الطريق» ← `IN_TRANSIT`. 2. عند الوصول والتفريغ يعلّم «تم التسليم» ← `DELIVERED`. 3. كل تحديث يولد حدثًا وإشعارًا.
**البديلة:** 2أ. تجاوز `expected_delivery_at + 2h` ← `DELAYED` (SYSTEM)؛ يستطيع الناقل إضافة ملاحظة تأخير؛ ثم `DELIVERED` من `DELAYED`.
**الاستثناءات:** E1 قفز حالة (`PICKED_UP` ← `DELIVERED` مباشرة) غير مسموح في MVP ← `409 INVALID_TRANSITION`.
**القواعد:** BR-053، BR-072. **الصلاحيات:** P-64، P-65. **البيانات:** shipments، shipment_events.
**معايير القبول:** AC1 المنجم والمصنع لا يستطيعان تعليم حالات التنفيذ.

## UC-025 — تحديث كمية المادة

| | |
|---|---|
| الفاعل الرئيسي | عضو جهة MINE |

**السيناريو الرئيسي:** 1. يدخل الكمية الكلية الجديدة. 2. تحديث مشروط: `WHERE :new_total >= reserved_quantity + sold_quantity` مع قفل الصف. 3. سجل تدقيق بالقديم والجديد.
**الاستثناءات:** E1 أقل من المحجوز + المباع ← `422 QUANTITY_BELOW_COMMITTED`.
**القواعد:** BR-010، BR-015. **الصلاحيات:** P-22. **البيانات:** material_listings، audit_logs.
**معايير القبول:** AC1 لا يمكن أن تصبح الكمية المتاحة سالبة حتى مع تحديث متزامن مع قبول.
