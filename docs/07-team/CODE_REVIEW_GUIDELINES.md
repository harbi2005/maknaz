# إرشادات المراجعة

[← فهرس الوثائق](../README.md)

> تنطبق على كل Pull Request: كود، وثائق، تصاميم مصدّرة، بيانات. الهدف حماية صحة المعاملات ودقة الادعاءات، لا الذوق الشخصي.

## 1. القواعد العامة

| القاعدة | التفصيل |
|---|---|
| لا دمج دون مراجعة | موافقة واحدة على الأقل من غير كاتب التغيير |
| مراجع من التخصص المتلقي | تصميم ← SE، بيانات ← SE + QA، كود ← QA يتحقق، وثائق عمل ← BD |
| مراجعة ثانية إلزامية | للتغييرات الحساسة في §4 (قائد الفريق أو SE) |
| حجم PR | تغيير واحد متماسك؛ PR يتجاوز ~400 سطر منطقي يُقسم ما أمكن |
| الرد | كل تعليق يُرد عليه أو يُحل؛ لا دمج مع تعليقات «Request changes» مفتوحة |
| النبرة | تعليق على العمل لا على الشخص؛ اقتراح مع السبب |

## 2. قائمة المراجعة العامة

- [ ] الوصف يربط التغيير بمعرفات FR/BR/UC/TS أو Issue
- [ ] التغيير داخل نطاق [MVP_SCOPE](../00-product/MVP_SCOPE.md)
- [ ] لا مواعيد أو تقديرات زمنية في الوثائق
- [ ] الروابط والمراسي تعمل (`python3 tools/scripts/validate_docs.py`)
- [ ] المعلومة موسومة: موثقة / متطلب معتمد / توصية هندسية / بيانات افتراضية / قرار مفتوح
- [ ] لا ادعاءات ممنوعة: ذكاء اصطناعي، تحليل كيميائي، صلاحية مادة، إذن نظامي، شراكات أو عملاء غير موثقين، أسعار نقل «موثقة»

## 3. قائمة الأمن

- [ ] لا أسرار ولا مفاتيح ولا كلمات مرور ولا رموز وصول في الكود أو الوثائق أو السجلات (`.env` خارج Git)
- [ ] كل نقطة API تتحقق من الدور **و**عضوية الجهة **و**كون الجهة طرفًا في الكائن (SR-01–SR-05)
- [ ] الوصول لكائن جهة أخرى يعيد `404` لا `403`
- [ ] لا مبالغ يرسلها العميل؛ الحساب على الخادم (SR-07)
- [ ] الإجراءات الحرجة تتطلب `Idempotency-Key`
- [ ] الملفات المرفوعة: نوع وحجم مقيدان، روابط موقعة قصيرة العمر
- [ ] لا بيانات شخصية في السجلات
- [ ] لا تعطيل للتحقق من TLS ولا تجاوز لفحوص CI

## 4. التغييرات الحساسة (مراجعة ثانية)

| المجال | لماذا |
|---|---|
| آلات الحالة والانتقالات | أي انتقال غير موثق يكسر دورة الصفقة |
| الحجز الذري والأقفال | خطر البيع الزائد |
| التسعير والتقريب والمبالغ | أخطاء مالية في الفاتورة |
| الدفع والاسترجاع المحاكيان | تكرار أو استرداد زائد |
| المهل والإلغاء التلقائي | إلغاء خاطئ أو مزدوج |
| الصلاحيات (RBAC) | تسرب بيانات بين الجهات |
| ترحيلات قاعدة البيانات | تغيير غير قابل للتراجع |
| `.github/workflows` | تنفيذ آلي في المستودع |
| الأرقام والإحصاءات المنشورة | مصداقية المشروع |

## 5. ما يُراجع بحسب النوع

| النوع | يُفحص |
|---|---|
| كود | الاختبارات تغطي المسار السعيد والحالات الحدية؛ رسائل الأخطاء من [API_SPECIFICATION](../03-architecture/API_SPECIFICATION.md)؛ لا ثوابت مهل خارج مصدر السياسة؛ المال بالهللة |
| وثائق | الاتساق مع المصدر المعتمد؛ لا تكرار متضارب؛ المعرفات صحيحة |
| بيانات | مطابقة [DATA_REQUIREMENTS](../02-requirements/DATA_REQUIREMENTS.md)؛ علم `is_demo`؛ لا أسماء شركات حقيقية |
| تصميم | الحالات الأربع، RTL، وسوم المحاكاة والتحقق والمسافة |

## 6. التعليقات

بادئات اختيارية تسرّع القراءة: `blocking:` يمنع الدمج · `question:` استفسار · `nit:` تحسين شكلي غير ملزم · `suggestion:` بديل مقترح.
